## Gate G3: security-critical tool pipeline (do **not** enable during G0–G2)

### G3.1 Normalize and bind tool intent

**ALGORITHM CONTRACT:** for every supported `ToolDefinition`, decode JSON into a **strict typed argument schema** with length bounds, required fields, destination validation and unknown-key policy. Example: `CalendarCreateArgs(title:String,startDate:Date,endDate:Date,calendarID:?)`, `OpenURLArgs(url:URL)`. Validate endDate strictly later than startDate and canonicalize destination (scheme, lowercased IDNA host, default port, explicit recipient). Create a canonical intent with ownerID, current session generation, exact toolID/schemaVersion, invocationID, normalized arguments, exact recipient, sensitivity classes, expiry and purpose. Hash a **versioned length-prefixed** deterministic encoding of *all* fields; recompute from the **same canonical typed intent** at approval and dispatch. A bare hash sent from the client back to the coordinator is **not independent recomputation**. SHA256 alone is a consistency digest, not a defense against a compromised local DB able to alter both payload and hash.
