## B. Verified P0: blocking defects

1. **Composition root / compile:** [`AppContainer.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/App/AppContainer.swift) passes `configurationRepository:` to `AssistantOrchestrator`, but [`AssistantOrchestrator.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/AI/Routing/AssistantOrchestrator.swift) accepts no such initializer argument. This is a direct cross-file compile contradiction.
2. **SwiftUI construction:** [`AdaptiveLayout.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/DesignSystem/AdaptiveLayout.swift) still calls `DashboardView(viewModel:)`, `TaskDashboardView(viewModel:)` and `SettingsView(viewModel:)`; the current views have no such initializers and own their view models through `@State`/`@Environment`. The Third commit did not reconcile these constructors.
3. **ModelRouter does not type-check as written:** [`ModelRouter.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/AI/Routing/ModelRouter.swift) has a recursive/redeclared `ProviderConfiguration.id` extension and synchronously calls actor-isolated `KeychainVault.hasSecret` from a synchronous filter. Its lookup also indexes a provider registry keyed by provider IDs (`groq`) using configuration UUIDs. Even after syntax repair, routes cannot match. A registered provider starts in an asynchronous task, creating a first-request race.
4. **The assistant still fabricates completion:** [`AssistantOrchestrator.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/AI/Routing/AssistantOrchestrator.swift) only emits `started` and `completed`. It never invokes `router.route`, `provider.stream`, context retrieval, provider fallback or message persistence. The most important product feature does not function.
5. **Broken approval compilation AND authorization:** [`ApprovalCoordinator.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Security/ApprovalCoordinator.swift) refers to `req.sessionToken`, `req.canonicalArguments` and `currentSession.generationID`, none of which exist in the canonical [`ApprovalRequest` / `SessionToken` models](https://github.com/prashantjadon311/ios-Ai/tree/5905602/PersonalAssistant.swiftpm/Domain). More importantly, payload and current session checks are optional in its public `approve` API; callers pass the defaults. This is **fail-open authorization design**, not a verified approval boundary. All model-proposed side-effect tools must stay disabled.
6. **No durable execution ledger:** [`ToolReceiptStore.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Tools/ToolReceiptStore.swift) holds receipts only in a `[UUID: ToolReceipt]` dictionary. `ToolInvocationCoordinator` calls it PREPARED but a crash erases the receipt. It does not provide crash-safe or idempotent side effects, irrespective of comments.
7. **Privacy controls are not enforced at transport:** [`PrivacyRoutingView.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Features/Configuration/PrivacyRoutingView.swift) saves preferences, but [`ModelRouter.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/AI/Routing/ModelRouter.swift) has no privacy-mode parameter or check and [`HTTPClient.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/AI/Transport/HTTPClient.swift) has no egress-policy enforcement. [`PrivacySettingsView.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Features/Settings/PrivacySettingsView.swift) also changes only local UI state. Treat the advertised 'Private Only blocks all external traffic' statement as unsupported.
8. **Policy reset on assistant switch:** [`AppSession.setActiveAssistant`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/App/AppSession.swift) reconstructs a fresh `AppPreference`, overwriting privacy mode, consents, appearance and locale when switching Maya/Saar. A private-only selection can silently revert to cloud allowed.
9. **The chat cannot consistently load a new conversation:** [`ChatView.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Features/Chat/ChatView.swift) passes `conversationID ?? ConversationID()` into its factory. The model interprets this arbitrary new UUID as an existing conversation and never enters its nil/create-new branch. [`DashboardViewModel.onAsk`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Features/Dashboard/DashboardViewModel.swift) discards the typed text. Completed assistant output is added to UI memory but not persisted. Swift 6 actor isolation of the `@Sendable` callback is also unverified.
10. **Provider setup cannot lead to a working route:** [`ProviderDetailView.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Features/Configuration/ProviderDetailView.swift) uses `try?` and always announces key-saving success, without creating/enabling a `ProviderConfiguration`. In [`OpenAICompatibleProvider.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/AI/Providers/OpenAICompatibleProvider.swift) providers created without `ownerID` return an empty `models()` result, and stream currently silently drops tool calls. Route/model configuration does not consistently reach the request.

## C. High-risk P1 functional/security/data findings

11. **False-green tests.** [`scratch/verify_matrix.py`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/scratch/verify_matrix.py) checks source substrings such as `"sessionToken"` and `"SSEDecoder"`, not behavior. [`scratch/test_chat_slice.py`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/scratch/test_chat_slice.py) itself requires `await router.route(`, `hasEmittedVisibleToken`, and `privacyMode == .privateOnly`, absent in committed orchestrator/router. Its published `4/4 PASS` claim is inconsistent with the committed code. A fixed absolute source path in the script also makes runs nonportable.
12. **Unverifiable run result.** There is no Apple SDK compiler log, iPad Swift Playgrounds import log, XCTest/Swift Testing harness, executed security test or CI workflow in the current tree. A Python bracket checker is not a Swift type checker.
13. **Network redirect policy missing.** [`HTTPClient.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/AI/Transport/HTTPClient.swift) comments promise safe redirects but uses shared `URLSession` and no redirect delegate. Default `allowedHosts=[]` imposes no host allowlist. This fails to enforce its claimed redirect policy; whether it actually leaks credentials has NOT been established.
14. **False stream completion.** [`OpenAICompatibleProvider.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/AI/Providers/OpenAICompatibleProvider.swift) emits completed after a stream ends even if no `[DONE]` or supported finish reason was received. It does not reconstruct streamed `tool_calls` and sends no tools even if offered. A truncation can masquerade as success.
15. **Tool ID contract split.** [`ToolRegistry.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Tools/ToolRegistry.swift) defines `createReminder`, `createCalendarEvent`, `openURL`, while concrete tools define `create_reminder`, `calendar_create`, `open_url`. A model proposal for those concrete IDs is rejected as unknown. [`CalendarTool.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Tools/CalendarTool.swift) returns 'Created calendar event' after permission approval without calling `EKEventStore.save`; `OpenURLTool` claims an opened link without actually launching it. These are false success paths.
16. **Unsafe URL validation scope.** [`URLSafety.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Security/URLSafety.swift) blocks a few literal hosts and prefixes but misses many private, IPv6, DNS rebinding and redirect cases. The final resolved destination and redirect chain need checking with tested policies.
17. **Task recurrence not idempotent.** [`TaskScheduler.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Tasks/TaskScheduler.swift) creates a fresh random occurrence UUID each time a schedule is recomputed; repeated scheduling produces different keys. [`TaskRepository.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Persistence/TaskRepository.swift) does fetch-then-insert without a persistent uniqueness enforcement. DST code still uses `TimeZone.current` instead of the task's stored timezone. No deterministic schedule/cancel/reschedule recurrence proof.
18. **Tasks can be saved but alerts fail silently.** [`TaskEditorView.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Features/Tasks/TaskEditorView.swift) swallows notification scheduling errors and dismisses the editor without identifying the task as unscheduled. It constructs a new scheduler on each save rather than using an app-owned task coordinator.
19. **Voice still lacks verified end-to-end ownership.** The new [`VoiceCoordinator.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Voice/VoiceCoordinator.swift) forwards audio buffers, a real improvement, but no complete Chat-to-VoiceCoordinator wiring or device test is present. The `AVAudioPCMBuffer` crossing actor/`Sendable` closures, permission requests, stale callbacks, interruptions and eventual text dispatch all require Apple compiler/runtime testing. The recognizer and coordinator are not registered as a service in `AppContainer`.
20. **Fictional offline AI capability.** [`CapabilityCenter.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/App/CapabilityCenter.swift) equates `canImport(FoundationModels)` and an iOS-18 runtime check with actual Apple model availability. Apple requires checking `SystemLanguageModel.default.availability` on eligible hardware/locale and a supported OS; the [`AppleFoundationModelProvider.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/AI/Providers/AppleFoundationModelProvider.swift) itself only returns unavailable and throws. Keep it disabled until a supported runtime implementation is tested.
21. **Avatars are placeholders, not images.** Maya and Saar `.imageset/Contents.json` files have no `filename` and no actual image resources. The UI draws SF Symbols inside circles. This does not meet the requested male and female avatar asset feature.
22. **Attachment data loss risk.** [`AttachmentLifecycle.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Media/AttachmentLifecycle.swift) writes referenced attachments to the caches directory and purges all files older than 24h without checking whether they are still attached to historical messages. Move durable user content to Application Support; retain orphan-only cleanup and privacy/access protection.
23. **Search/memory largely disconnected.** [`HistorySearchCoordinator.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Search/HistorySearchCoordinator.swift) filters only conversation titles and never uses its `LocalTextIndex`; the in-memory index has no persisted owner-scoped restore; `ContextBuilder` and `MemoryProposalEngine` are zero-byte. A functional memory retrieval/context pipeline is not established.
24. **Auth/lock state unbound to navigation.** [`AppSession.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/App/AppSession.swift) exposes `isLocked`, but [`AdaptiveLayout.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/DesignSystem/AdaptiveLayout.swift) doesn't gate its five screens on it. Do not claim Face ID protects app history until this flow is wired and tested.
25. **CoreSpotlight privacy.** [`SpotlightProjection.swift`](https://github.com/prashantjadon311/ios-Ai/blob/5905602/PersonalAssistant.swiftpm/Search/SpotlightProjection.swift) comments require opt-in but index writes occur without a checked owner/user opt-in or a namespace per owner. Confirm indexing policy and purge on account switch/delete.
26. **Versioned schema drift.** Third modifies existing `SchemaV1` to add `StoredAttachment`, while versionIdentifier remains `1.0.0`. If any prior build has already shipped/created a V1 store, use a migration stage; otherwise document that V1 is not yet frozen. Do not silently reset a store.
27. **UI presentational stubs remain.** `SettingsSubViews.swift` still has placeholder Appearance/Diagnostics/Storage/Security sections; `ApprovalCenterView` always claims no requests and doesn't bind its view model; `ToolPermissionsView` toggles are local UI only and never persist or enforce grants; assistant name editor doesn't update repository. Disabled Clear All Data is safer than fake deletion but is not completed product scope.
28. **Missing on-device capability/privacy evidence.** No real Maya/Saar images, no image asset filenames, no confirmed microphone/speech/calendar/reminders/Face ID purpose strings/capabilities, no device logs and no App Store privacy-flow audit. Apple documents protected capability setup in Swift Playgrounds. `PrivacyInfo.xcprivacy` alone does not configure all usage-description prompts.
29. **Do not rerun code generators.** `scratch/gen_*.py` files are committed. Running them over repaired files risks overwriting hand-edited fixes. Preserve them as historical scaffolding unless diffed and explicitly approved.

## D. Exact release gating

- **Red:** source-level contradictions exist; don't transfer the unmodified package and assume an iPad will compile it. Do not activate external tool execution.
- **R0:** snapshot local git/status and reconcile against `5905602` without destroying uncommitted work; update current checkpoint based on actual files, not the historical text.
- **R1:** repair mismatched initializers, duplicate/redeclared symbols, async actor calls, canonical DTO consistency, iOS API availability, SwiftUI and SwiftData ownership; get real `AppModule` compiler output when Apple tooling is available.
- **R2:** produce a **real** BYOK chat vertical slice: enable provider config, select a model, create/reopen conversation, stream complete text through router/provider/SSE, persist user/assistant messages, handle cancellation and interrupted streams. Verify with executable Swift mocks, not regex.
- **R3:** enforce privacy at every egress point, deny tools until real single-use/session-bound approvals and persistent PREPARED receipts exist, test crash recovery and redirects.
- **R4:** complete one real task/reminder and one real tap-to-talk workflow; preserve durable attachments; connect profile editing and avatars.
- **R5:** compile/import in actual iPad Playgrounds, verify capability purpose strings/asset bundling, run device tests and then update evidence from `NOT_RUN` to `PASS` where supported.

**Source of truth:** committed code and executable test evidence outrank comments, historical reports, generated checklists and statements of completion. The 46/46 regex checklist is not 46 functional test passes.
