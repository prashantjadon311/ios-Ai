## 2. Critical source-level compile and integration defects (P0)

1. **Observable environment regression.** `App/AppContainer.swift` removed `@Observable` while `MyApp.swift` injects `container` using `.environment(container)` and many views read `@Environment(AppContainer.self)`. That SwiftUI overload requires an `Observable` class. Restore correct observation/injection contract rather than changing each view blindly. Apple: https://developer.apple.com/documentation/swiftui/view/environment(_:).
2. **App factory still incompatible.** `AppContainer.makeChatViewModel` passes five inputs; the revised `ChatViewModel.init` requires `orchestrator` and `configurationRepository` too. The new container also no longer constructs/exposes an orchestrator or router, so chat cannot run even after resolving syntax.
3. **Duplicate global SwiftUI view names.** `Features/Configuration/ConfigurationView.swift` still declares `AIConfigurationView`, `ModelPickerView`, `PrivacyRoutingView`, `ProviderListView`, `ProviderDetailView`, `VoiceConfigurationView`, `ToolPermissionsView`, `AssistantProfileView`, and `MemoryBrowserView` as placeholders; new dedicated source files now declare the same names. A single `AppModule` target cannot contain these duplicate top-level types.
4. **Navigation factory contract mismatch.** New `DesignSystem/AdaptiveLayout.swift` instantiates `DashboardView(viewModel:)`, `TaskDashboardView(viewModel:)`, `HistoryView(viewModel:)`, and `SettingsView(viewModel:)`. Their checked existing implementations own private `@State` view models, with no corresponding exposed initializer. Choose one navigation/DI pattern and implement it consistently.
5. **Domain DTO changes not propagated.** `Domain/Message.swift` declares `ContextMessage(role,parts,source,sensitivity)`, but `AI/Context/ContextBuilder.swift` and `Features/Chat/ChatViewModel.swift` pass a nonexistent `provenanceHash:`. `ChatViewModel` also constructs `MessageRecord` without mandatory `source` and `sequenceNumber`, and matches `.toolResult` as if it had three associated values, whereas its canonical declaration has two. Resolve against the canonical model, not by inventing another duplicate DTO.
6. **Independent invalid symbols in newly generated UI.** `Features/Assistant/AssistantProfileView.swift` uses nonexistent `AssistantProfile.avatarType`, `.name`, and `.voiceIdentifier` rather than `avatarRole`, `displayName` and `voiceSettings.voiceIdentifier`. `PrivacyRoutingView.swift` and `Security/PrivacyPolicyEngine.swift` use `PrivacyMode.standard`, although the domain enum has only `.privateOnly` and `.cloudAllowed`.
7. **Task model divergence.** `Tasks/TaskEngineActor.swift` and `Features/Tasks/TaskDetailView.swift` use nonexistent `TaskDefinition.scheduleTime`; `Tasks/TaskScheduler.swift` uses nonexistent `.recurrenceRule`; `TaskRecurrence.swift` depends on undefined `RecurrenceRule` instead of the domain `TaskRecurrence`. The scheduler's string occurrence key also conflicts with the canonical structured `TaskOccurrenceKey`.
8. **Tool/error-state mismatches.** `Tools/ToolInvocationCoordinator.swift` writes receipt status `.completed`, while `Domain/ApprovalRequest.swift` defines `.succeeded`, `.prepared`, `.failed`, `.ambiguous`. It calls `AppError.sideEffectAmbiguous(operation:)` where the enum requires `operationKey:`. `Security/PrivacyPolicyEngine.swift` uses nonexistent `AppError.privacyDenied(reason:)`. `Voice/LegacySpeechRecognizer.swift` uses unsupported `AppError.unsupportedCapability(name:)` rather than the unlabeled enum case.
9. **Attachment API and persistence contradictions.** `Media/AttachmentProcessor.swift` calls `AttachmentValidator.validate(data:expectedMime:)`, but the validator exposes `validate(data:claimedMime:)`. `Persistence/AttachmentRepository.swift` uses `StoredAttachment`, absent from the unchanged sole `StoreModels.swift` and `SchemaV1.models`. Design a legitimate additive migration if adding a new stored entity to an existing store; do not silently reset old user data.
10. **Other nonexistent model properties.** `AI/Context/MemoryProposalEngine.swift` passes `scope: .general` to `MemoryItem`, which has no `scope` field. `ContextBuilder` likewise contradicts canonical context declarations. These are independently checkable source-level blockers; the reported zero broken references is not credible.

## 3. Runtime, agent-safety and data-integrity defects (P0 if feature enabled)

11. **End-to-end chat still not connected.** The published `AI/Routing/AssistantOrchestrator.swift` is identical to its placeholder baseline: it emits a `pending-provider` start and an immediate completion without routing, making HTTP requests, streaming or persisting a real assistant turn. The new `ChatViewModel` calls this stub. The new provider files do not create a functioning user interaction by themselves.
12. **Router/provider inconsistency.** Unchanged `ModelRouter` still declares a recursively self-referential `ProviderConfiguration.id` extension, invokes an actor Keychain method from synchronous filtering, and keys registered providers by config UUID while `GroqProvider/OpenRouterProvider` identify themselves by literal provider name. `AppContainer` does not register providers. Real routing and fallback are therefore not established.
13. **The provider ignores user's model choice.** `OpenAICompatibleProvider.stream()` hardcodes a Groq or OpenRouter model string rather than taking the selected model. `models()` returns an empty catalog for wrappers created without a bound owner. New `ModelPickerView` stores selection in local `@State`; it is not a persisted provider setting. The SSE code handles text/usage but does not assemble streamed tool-call fragments or validate all terminal cases.
14. **Tool ledger is not durable.** New `ToolReceiptStore` uses only an in-memory dictionary. It is lost on process termination, contradicting the report's *durable PREPARED before side effect* guarantee. `recordPrepared` unconditionally replaces an existing receipt for an identical ID. `ToolInvocationCoordinator` can replay a side effect after reboot; generic catch marks uncertain failures `.failed`. Tool IDs also differ between `ToolRegistry` (`createReminder`, `createCalendarEvent`, `openURL`) and concrete tools (`create_reminder`, `calendar_create`, `open_url`). Do not expose autonomous external writes until this is fixed and tested.
15. **Approvals are not completed authorization.** `ApprovalCoordinator` stores approvals in memory, takes `expectedPayloadHash: Data? = nil`, does not enforce expiration or current session, and returns `ApprovalRequest` instead of an `AuthorizedToolCall` bound to exact reviewed parameters. `ApprovalViewModel` silently ignores failures. ToolPolicyEngine fixed the prior tautological comparison but only checks `session.userID == ownerID`; it does not establish current authenticated session, complete schema validation or full destination-aware consent.
16. **Privacy-mode UI is not an outbound enforcement boundary.** `PrivacyRoutingView` changes only its local `@State`. Older `PrivacySettingsView` also has no persistence. The new `PrivacyPolicyEngine` cannot compile due to `.standard`. The actual HTTP/provider routing path does not centrally enforce account-specific privacy mode, sensitivity, consent, or server destination before every upload. Default `.cloudAllowed` is not proof of consent.
17. **Account/session barrier exists mostly on paper.** Repository functions accept `SessionToken` yet perform writes without comparing with a current token. New `ChatViewModel` callbacks mutate UI after `await` without a demonstrated current-session check. `AppSession.switchProfile` rotates token but doesn't itself wire cancellation into active chat, recording, indexing, tool and task operations.
18. **BYOK failure is concealed.** `ProviderDetailView` uses `try?` for Keychain writes but unconditionally displays “Key saved securely.” `KeychainVault.setSecret` deletes the old key before an attempted add, so a write failure can destroy a working previous secret. The user must get a typed, truthful result and atomic update where supported.
19. **Networking guardrails are incomplete.** HTTP uses `URLSession.shared` with default redirect behavior and an empty-by-default host allowlist. `URLSafetyValidator` only blocks a few literal IPv4/IPv6 addresses and two private IPv4 prefixes, not comprehensive DNS/private address/rebinding/redirect cases. No demonstrated prevention of authorization header leakage on unsafe redirect or custom endpoint. Restrict custom endpoints and review iOS URLSession redirect behavior before shipping.
20. **Device lock is not an app authorization gate.** `AppSession.isLocked` isn't enforced by the published root navigation path, while `BiometricGate` returns `true` in its `#else` (unsupported) path. Fail closed and require an explicit, tested lock/unlock UI flow.

## 4. Features whose reported completion is unsupported

21. **Voice pipeline:** `MicrophoneCapture` installs an audio tap but drops buffers; `LegacySpeechRecognizer` creates a recognition request but no code feeds it those buffers. `ModernSpeechTranscriber` is a fallback wrapper, not the Apple newer engine. Tap-to-talk cannot be called functional without wiring and on-device tests.
22. **Tasks:** `TaskEngineActor` references wrong fields; local reminders are not centrally connected to task saving, recurrence or notification reconciliation. Recurrence algorithm is not proven against DST/duplicate-occurence fixtures. A notification is not background AI execution.
23. **Search/memory:** `LocalTextIndex` is volatile and not owner-partitioned internally; `HistorySearchCoordinator` ignores the index and only searches conversation titles. `ConversationSummarizer` merely truncates the oldest messages rather than generating a provenance-aware summary. `ContextBuilder` elevates passed memory text into a system-role message without independently checking verified owner/sensitivity/token budgets. `MemoryItem.init` ignores `isDeleted` argument and always sets it false, so round-trip state may be lost.
24. **Media:** `AttachmentValidator` checks only selected magic bytes and 20MB length. It cannot justify claims about PDF structural safety, page/time limits or all spoofed formats. Saved files use a caller-supplied filename without a complete normalization/bounds policy. `VisionTextRecognizer` uses ImageIO symbols but does not import ImageIO explicitly; platform typechecking is required. Attachment processing is not proven cancellation-safe or integrated with chat.
25. **UI/personalization:** Asset-catalog manifests for Maya/Saar have no image filename and the published tree has no actual avatar image bytes; `AvatarView` draws an SF Symbol gradient. Provider/model/voice/tool toggles mostly remain local transient state. `SettingsView`'s “Clear All Data” button has an empty destructive-action handler. This is a dangerous false affordance.
26. **Apple model false availability:** `CapabilityCenter` returns true when `canImport(FoundationModels)` and iOS >=18, without checking actual on-device `SystemLanguageModel.default.availability`, device eligibility, supported OS, region or download state; `AppleFoundationModelProvider` always throws. A supported model should be detected only using the documented SDK API and guarded by genuine compile availability.
27. **Shipping package:** `Package.swift` still contains no capabilities or explicit resource declarations and is marked Apple-generated. Swift Playgrounds capability/purpose strings and inclusion of resources must be confirmed in an actual exported Playground and real build. Current localization strings exist but that alone does not prove any view uses localized keys.
28. **Unsupported verification claims:** New `docs/implementation/W13_W14_VERIFICATION_AND_HANDOFF.md` reports 46/46 PASS via `scratch/verify_matrix.py`, but this script is a committed zero-byte file. It also claims zero TODO placeholders while `ConfigurationView.swift` and `SettingsSubViews.swift` still have many visible placeholders; claims zero broken references despite multiple exact domain mismatches. `TokenBudget.swift` and `RetryPolicy.swift` remain zero bytes while the report names their algorithms as implemented. This is a **documentation evidence failure**, not just unfinished functionality.
29. **No executable tests or CI found:** The recursive tree includes no populated tests, fixtures or GitHub Actions workflows. The 16/16 handoff validator checks documentation structure; its PASS is not Swift typechecking, unit testing, simulator testing, privacy validation or actual iPad import.
30. **Recovery documentation is incomplete:** `docs/implementation/R0_SOURCE_RECONCILIATION.md` is empty. The existing implementation checkpoint should not say fully implemented/verified until it reconciles committed source with these concrete blockers. Preserve past documents as historical evidence, append an independently sourced correction instead of rewriting history.
