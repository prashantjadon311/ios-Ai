# V3 critical algorithms and exact recovery rules
This document augments V2 03 and 11. Its stronger rules override V2 when they conflict. Method naming is normative at the semantic level; verify exact Swift API signatures against installed SDK during W00.

## B01 — Byte-correct Server-Sent Events decoder
Input: AsyncSequence<UInt8/Data> from URLSession. Output: `SSEFrame(event: String?, id: String?, data: String)`; storage limit default 256 KiB per frame, total stream configurable. 1) Append incoming bytes into one bounded buffer. 2) Find LF byte; slice one raw line, strip single trailing CR. 3) Decode *complete* line as UTF-8 strictly; if invalid emit protocol error, never split multi-byte Unicode midline. 4) Blank line emits accumulated frame only if at least one `data:` line; otherwise reset. 5) `:` prefix comment is ignored; parse first colon only; strip one leading optional ASCII space from value. 6) Join repeated `data:` values with LF; accept `event:` and `id:` but reject NUL in ID. 7) At EOF, process terminal nonempty line only if allowed by provider protocol, then emit pending event or throw incomplete event according to adapter spec; do not conceal corrupted JSON. 8) Cancellation closes underlying URLSession task and bounded AsyncThrowingStream continuation. Tests: every possible byte-split offset for multibyte emoji; CRLF; multiple data; comments; oversized frames; EOF without blank line; invalid UTF-8.

## B02 — Provider text and tool delta assembly
Provider wire decoder maps raw SSE JSON into provider-specific incremental events. Key each proposed tool by `(choiceIndex, toolIndex or providerCallID)` and require stable `toolName` and response schema version. Append bounded argument byte fragments (default 64 KiB); enforce monotonic per-stream sequence. A tool call is executable *only after* provider terminal tool-call completion, strict JSON parse, exact typed schema validation, policy check, owner check and (if required) approval. On failure/cancel/provider fallback discard incomplete fragments. Never construct a callable tool from partial text. One trace produces at most one visible terminal event.

## B03 — Model routing and fallback transaction
For each user turn freeze `traceID`, owner/session, privacy mode, required modality/tool/JSON/context, approved egress destination, token budget and cost advisory. Filter candidate models in order: verified capabilities; active provider credentials; model available; permitted data destination; enough context; provider health; local advisory budget; user preferences; stable configured order. Unknown required capability excludes model. Before first emitted token or external side effect, provider error MAY select another route with *same or stronger privacy* and a new attempt under same trace. After first visible text, approval proposal or any tool side effect, automatic fallback is prohibited: persist partial result as interrupted, notify user, offer explicit new attempt or continuation. Streaming UI must tag active provider/attempt; never concatenate unrelated generations. All attempts settle usage once by attempt ID, replacing estimates with actual if and only if authoritative usage arrives.

## B04 — Context construction and token budgeting
Inputs current user turn, trusted application safety/tool policy, current owner/assistant, conversation message window, explicitly saved memories, optional lexical retrieval, privacy policy and chosen model context capacity. Reserve output tokens and tool schema overhead first; deterministically order high-priority policy + current user command, then recency-limited conversation, then permitted verified memories, then tagged untrusted retrieved text. Remove secret items entirely and personal/sensitive items disallowed for selected destination. Only summarize old history using authorized model/route and store summaries as *derived unverified* with source IDs and revision. Estimate token count conservatively; when required trusted prompt+current request exceeds available context, return `contextTooLarge`, never silently truncate active instruction. On memory deletion invalidate context cache and index before next turn. Hash context source/revision IDs for audit, not raw private content.

## B05 — Tool authorization and durable receipt
Accept `ToolProposal(id, owner, trace, toolID, version, exact decoded typed args, input-source tags)`. Reject unknown tool/version/field/type, origin mismatch, content-derived unauthorized privilege, destination not on allowlist and expired session. Canonicalize approved DTO through exactly one tested stable representation: sorted coding keys, normalized Unicode/URL representation where required, typed decimal/date representation and a schema-defined field order. Compute SHA-256 over length-prefixed fields including owner, session generation or stable permission lease, tool/version, normalized destination, sensitive-data categories, canonical args, permission scope and approval expiry. Approval is one-use atomic transition protected against double tap. Before execution re-evaluate owner/session/permission/destination/data-sensitivity/budget and recompute digest. Persist `PREPARED` + unique operation key **before** external side effect. If executor has verified remote idempotency-key support, send same persisted operation key; otherwise any timeout after dispatch produces `AMBIGUOUS`. Reconciliation must not resend non-idempotent operation without an independent verification or explicit human action. Audit contains redacted inputs, outcome and external reference only. No 'completed' until success receipt is durable.

## B06 — Task scheduling, edit and recovery
TaskDefinition immutable ID and revision plus recurrence timezone/calendar and requested local wall-clock time. TaskRun key `(taskID, definitionRevision, scheduledOccurrenceID)`. Compute next occurrence using Calendar matching with a specified DST policy: nonexistent local times choose next valid time, repeated wall time chooses first instance, never schedule second duplicate. Materialize only a bounded horizon; persist notification request IDs. On edit: invalidate queued future runs for old revision and remove corresponding pending notifications before scheduling new revision, retaining past audit. On launch: query pending notification identifiers and reconcile DB; any persisted `running` mark `interrupted`, any unresolved external PREPARED mark `needsReview`, restart *read-only/idempotent* steps only if policy permits. Never mark TaskRun done from notification delivery: user-notified vs work-completed are separate fields. Server-scheduled future AI jobs are outside V1.

## B07 — Voice lifecycle and stale event exclusion
Finite states idle → permissionRequest → capturing → transcribing → modelThinking → toolActing → speaking → idle. Monotonically increasing voiceSession UUID per start; every callback includes it; drop stale callbacks after stop/restart/account change. Begin only from direct user intent and valid permission. Stop TTS before capture. Audio interruption, app background if not supported, permission revocation and route changes stop capture, cancel recognizer, clear buffers, release AVAudioSession, mark session stopped. Only final recognized transcript submits one user turn, guarded by transcript sequence/dedup marker. Cloud STT requires separate informed opt-in and permitted data classification. Text/visual button remains available when STT unavailable.

## B08 — Local search, cache and deletion
Lexical search must always work: normalize/tokenize with locale and Unicode handling; owner+soft-delete filter inside repository; score title/phrase > word overlap > recency; stable pagination `(score, timestamp, UUID)`. Core Spotlight is optional opt-in index of explicitly user-approved non-sensitive projections only. Search index hits revalidate owner, deletion flag and current permission against source-of-truth DB. Deleting conversation, file or memory writes tombstone, cancels active index work, invalidates context/search caches, deletes temp resources, removes Spotlight item and queues optional future cloud purge. If purge fails, record pending status and avoid serving stale item.

## B09 — Attachment safety
Use security-scoped file picker URLs only for the lifetime of reading, copy through bounded streaming to app-scoped temp path, check byte size before and during copy, sniff signatures/type instead of trusting extension, reject directory/symlink traversal and protected-file denial. Images normalize orientation and optionally strip metadata in memory; set pixel budget, thumbnail cap and never upload full-res when tool requests only OCR. PDFs bound byte count, page count, OCR runtime and decompression limits; encrypted files explicitly unsupported unless user handles password locally. Tag extracted text untrusted; require privacy egress decision before any cloud upload. Delete temp on failure/cancel/account switch.

## B10 — Keychain and local storage security
Store ONLY user-owned API keys in Keychain service namespace `(bundleID, localOwnerID, providerID, purpose)`, appropriate `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` where device-only lifecycle is acceptable. Do not promise sync for device-only secrets; on device restore ask re-entry. Device lock can legitimately return inaccessible, distinct from missing. Protect private app files using available NSFileProtection modes; no blanket E2EE claim since system backups/provider copies have different guarantees. SQLite/SwiftData store migration failure must not be 'fixed' by deleting data; preserve copy and offer diagnostics/recovery. Exports omit keys, default encrypt sensitive archives when backup functionality is actually implemented.

## B11 — Actor ownership and memory pressure
`@MainActor` for presentation and app session; `actor` for routing/health/budget/tool ledger/task state; dedicated `@ModelActor` or serial persistence actor for ModelContext (verify supported SDK). Transfer Sendable DTOs across actors, never @Model instances or ModelContext. Streaming uses bounded buffering and UI delta coalescing; large media in files not giant model strings. Structured `Task` children propagate cancellation; detached tasks require explicit lifetime owner and documentation. Account switch changes generation and cancels all old work before rendering new owner.

## B12 — Failure handling table
| Failure | Durable state | Automatic behavior | User-facing recovery |
|---|---|---|---|
| 401/403 AI provider | providerAuthInvalid | no retry with same secret | re-enter/change own key |
| 429 with Retry-After | rateLimited until timestamp | eligible unstarted alternate route only | show cooldown/choice |
| 5xx pre-stream | retry bounded with jitter per read-only policy | eligible equivalent privacy route | retry later |
| 5xx after emitted tokens | partial/interrupted | no implicit model switch | explicit restart/continue |
| Cancel before tool dispatch | canceled | cancel descendants | retain partial history if user policy |
| Cancel after prepared tool | ambiguous if dispatched unknown | no blind retry | inspect execution receipt |
| Permission revoked before action | denied | no action | regrant/open Settings |
| Notification denied | unscheduled (definition saved) | no claim reminder active | permissions instructions |
| Store migration error | recoveryRequired | preserve original | read-only export/diagnose |
| Speech locale unsupported | unavailable | no implicit cloud STT | pick locale or type |

### Machine-verifiable side-effect policy
`PREPARED` MUST be durably written before dispatch. If a dispatched external write times out with no verified remote response, record `AMBIGUOUS` and enforce **no automatic replay**. The user or verified remote idempotency lookup must reconcile the result. Never mark AMBIGUOUS as completed or automatically regenerate a new operation key for the same proposed effect.
