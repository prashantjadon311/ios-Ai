# 03 — Deterministic algorithm cookbook for Claude Sonnet

All steps are implementation instructions, not evidence of working source. Use the exact contracts in `02_CANONICAL_CONTRACTS.md`; keep pure functions and actor wrappers separate. Every algorithm lists invariant, happy path and failure path. Unit-test pure parts with injected clocks, UUID generator, networking and repositories.

## A00: launch and session generation
1. Decode `PublicConfig.json` with strict known schema; validate origin HTTPS allowlist and fail gracefully on malformed file.
2. Open SwiftData versioned store without deleting it on migration failure; show recovery UI if opening fails.
3. Create local owner profile if empty; establish `SessionToken(userID, randomGeneration)`; seed two assistant profiles if and only if absent.
4. Wire `AppContainer` once with actor-confined repositories; all reads include owner ID. Start capability probe asynchronously.
5. On account switch/background lock: increment generation, cancel old streams/task runs/microphone, clear transient caches and previous owner's optional Spotlight index, then bind new owner.
6. Every async callback/DB write/UI state publish compares captured token to current token; discard stale results. Tests: 2 owners, delayed AI callbacks and task updates crossing switch.

## A01: incremental SSE parser (byte-correct)
- State = bounded incoming `Data` buffer (max 1 MiB per frame), event fields `dataLines`, optional `eventName`, `id`, `retry`, decoder state and finish flag.
- Append incoming bytes; split frames by either `\n\n` or `\r\n\r\n` without assuming chunks align; do not decode incomplete UTF-8 sequences by dropping bytes.
- For each completed frame, split its lines; ignore comment lines beginning `:`; concatenate multiple `data:` lines with newline; preserve `event:` and `id:`. Empty line dispatches one frame. Unknown fields ignored.
- Honor provider `[DONE]` sentinel only where specified by provider wire adapter; do not treat `[DONE]` as a generic transport primitive. Reject malformed/oversized frames and cap entire response budget.
- In OpenAI-compatible adapter: `delta.content` => text event, partial `delta.tool_calls[index].function.arguments` => append to index-specific bounded buffer until finish; parse complete JSON then strict schema check. Capture provider-supplied usage once. At most one completed event. On stream cancellation close URLSession task and mark partial reply cancelled.
- Fixtures: each byte boundary, CRLF, multiline data, malformed UTF-8, comment heartbeat, tool args fragmented across 50 chunks, missing `[DONE]`, oversized frame, duplicate finish, timeout.

## A02: model selection and privacy
Input `requirements, session, privacyMode, budget, registrySnapshot, healthSnapshot`. Filter by enabled+verified connectivity; required capabilities all `.yes`, not `.unknown`; context capacity >= required including response reserve; route must allow request's effective sensitivity and user consent. Apply per-request dollar/token budget, health cooldown, explicit preferred model then stable user-chosen priority and provider/model ID lexicographic tie-break. Return route decision with reasons excluding rejected providers and privacy-safe diagnostics. If no model, return typed reason; NEVER weaken privacy or send sensitive attachments to an unapproved fallback. Use live catalog refresh behind TTL/ETag, retain bundled conservative fallback but label unknown/unverified and require explicit probe before tool/vision use.

## A03: provider health and costs
Each provider stores failures in a rolling 5-minute window; auth failures latch until credential edited; HTTP 429 honors parsed integer-seconds or HTTP-date `Retry-After` (cap malformed/unbounded values). For network/5xx retry a safe generation request at most 2 times with full-jitter backoff: uniform[0, min(8s, 0.5s * 2^attempt)]. Three transient failures in 5 minutes OPEN breaker for 60s; after 60s HALF_OPEN allows exactly one probe; success CLOSES, failure reopens. These counts are proposed defaults in one configuration file, not hardcoded throughout. Budget actor reserves estimates before call, reconciles actual values if usage present, marks estimates otherwise, and never underflows; direct BYOK budget is advisory, not a provider-side hard billing guarantee. Under no condition does provider fallback re-execute an external tool side effect.

## A04: one assistant turn
Persist user message `pending`; snapshot owner/session/privacy and assistant profile; classify content and validate attachment sizes; build minimum necessary context. Reserve budget, select model; persist model-invocation start; enter bounded loop (max 6 model continuations, 10 total tool proposals). For each stream event enforce monotonic index and current session; coalesce text delta to at most ~20 UI publishes/second; batch durable partial message checkpoints at logical boundaries and on cancel. A tool proposal enters ToolPolicy (never direct invocation); return validated user-approved receipt as tool result; only then continue model. On valid final complete, commit complete assistant message and usage once; on fail/cancel store partial with explicit status and offer safe retry as new invocation. Callbacks for old trace IDs never mutate active conversation.

## A05: context allocation and memory
Budget = min(verified context length, user hard max) - explicit response reserve - overhead margin. Because tokens vary by provider, use provider tokenizer when available; otherwise a conservative estimate (e.g. ceil(UTF8_bytes/3)) and enforce truncation. Keep system policy + explicit user turn; add recent chronological turns until soft share; add capped verified memories relevant by lexical overlap/tag priority, recency and user pin; summarize older allowed history with source IDs but never invent citations. Memory admitted by user confirmation; AI proposals default unverified. Store source message IDs and revisions; contradictory verified facts produce review state, never silent overwrite. Expiration removes memory from context and any derived indexes.

## A06: tool authorization and idempotency
Parse full JSON with strict per-tool schema and bounded input; deny any unknown tool, unknown argument, owner mismatch, unsupported capability or source-only instruction. Compute `SHA256` of canonical action payload and destination; classify read/write/delete/external-send and sensitivity. Check tool-specific granted scope and current session, run explicit approval UI for sensitive actions binding exact hash and expiry; after approval recheck hash/permission/session. Write PREPARED receipt with stable operation key before platform call. On returned success persist SUCCEEDED and external ID; on clear rejection FAILED; on timeout/unknown result AMBIGUOUS and require human reconciliation. Never auto retry ambiguous writes; use undo only if supported and authorized. Tests include prompt injection in attachment, revoked permission, edited recipient after approval, duplicate model tool event and mid-flight logout.

## A07: task scheduling and run recovery
Represent schedule as calendar components + IANA timezone + recurrence spec + missed-run policy. Use Foundation Calendar to compute next occurrence after a specified instant, explicitly handle nonexistent/ambiguous local times with documented policy: if local time skipped by DST, advance to next valid local occurrence; if repeated, choose first occurrence. Persist occurrence key from task ID + definition revision + calendar occurrence ID and unique constraint/check. For reminders schedule `UNCalendarNotificationTrigger`, save UNRequest ID, reconcile edits by replacing corresponding pending requests; permission denial leaves task visible with alert disabled. Scheduled AI work while terminated is **not** executed locally; keep `WAITING_FOR_APP` unless remote scheduler installed. On cold start `running` transitions to `interrupted`; inspect last step receipts; resume only read-only/idempotent work; mark ambiguous external writes `needsReview`. Cancel must request child cancellation and accurately report side effects already committed.

## A08: voice state and audio lifecycle
Start only after explicit button tap and authorization; create new voice session sequence and configure `AVAudioSession` for input; capture bounded audio frames and dispatch to supported locale recognizer. On each partial transcript compare session ID and sequence, suppress stale/out-of-order; final transcript exactly once enters assistant turn. On `thinking/acting/speaking` reflect state in avatar; native TTS receives sentence segments and delegate callbacks; interrupt stops TTS and drops buffered chunks before reentering `listening` after explicit user input. Route change, phone call, permission revoke or app stop ends capture, releases audio session and deletes unnecessary temporary audio; never promise always-on voice. Unsupported Hindi/Hinglish locale provides visible selection/fallback explanation; cloud STT only after separate opt-in.

## A09: search/index privacy
Canonical search scans owner-scoped stored title/body normalized with locale-aware case/diacritic folding; tokenize safe Unicode word boundaries. Deterministic score = 5*exactTitleMatch + 3*phraseBody + 1*tokenOverlap + boundedRecencyBonus; tie break newest then stable ID. Filter owner and non-deleted before scoring; paginate. Optional Spotlight indexing only on explicitly opted-in non-sensitive content; index holds source IDs, not a second authoritative database. Every delete/profile switch calls index deletion; if stale index hit, re-verify DB owner + privacy before returning any result. Semantic Spotlight capability is conditional; never claim guaranteed semantic results on unsupported device.

## A10: attachment intake
Picker result -> security-scoped access when needed -> safe copy into unique temporary app-private path -> canonical path containment check -> inspect actual bytes/type rather than extension -> 10 MiB generic-file and 20 MiB image configurable defaults -> hash stream SHA256 -> duplicate only within same owner -> image downscale while preserving orientation -> optional metadata strip according to user policy -> PDF text via PDFKit (page/time limits) or Vision OCR on images -> redacted preview -> only upload when selected provider supports modality and disclosure policy allows. Reject unknown executable/archive or decompression bombs for V1; cap OCR pages, extracted text size and processing duration. Use atomic temp-to-final move and a cleanup journal on interruption.

## A11: account, privacy, quotas
Data classification must not be delegated solely to a model. Deterministic rules first: API secrets never included; Contacts/files sensitive by source; untrusted content retains source label; user can tighten classification but not relax privileged secrets by prompt. Every network export path has a single privacy gate with destination hostname, categories and user approval. Local Keychain key uses `kSecAttrAccessibleWhenUnlockedThisDeviceOnly` where compatible with requirements; BYOK secrets scoped per-user, never bundled. Direct BYOK mode does not offer server-enforced usage caps. Shared managed mode must validate session and enforce authoritative server quota before provider calls, post-V1 only.

## A12: offline/reconnect and optional cloud sync
Offline: local CRUD and history function, AI model request becomes explicit queued **draft** only if user chooses; never replay automatically on reconnection if privacy conditions changed. On reconnect refresh route and credentials, ask before newly cloud-bound content; avoid connectivity busy-wait. Future Firestore: per-user auth UID in rule-matched namespace; revisioned upsert/delete tombstones, conflict preview for sensitive edits; validate rules via emulator. Future Drive backup: encrypt on device with AES-GCM, per-archive nonce, authenticated header, user-held recovery secret derived using platform-supported KDF; dry-run restore, recovery-key wrong/tampered blob fails without importing; no plaintext cloud backup, no API keys by default.

## A13: deterministic provider configuration tests
For every real provider adapter, implement `models()`, `stream()`, error mapping and auth handling through shared HTTP transport, with no hardcoded guaranteed working model ID. Probe user-selected discovered model for tool/vision support using provider-advertised capability and, when needed, bounded test call. If an OpenAI-compatible endpoint lacks tool streaming, mark unavailable rather than producing invalid tool proposals. Every configured endpoint must use HTTPS except user-approved loopback development endpoint, with redirects blocked across host unless explicitly trusted.

## A14: UI reducers and accessibility
Each screen view model exposes `loading|ready|empty|permissionRequired|failed` plus immutable view state; all user interaction routes through `ApplicationCommandBus`. iPad navigation uses `NavigationSplitView`, compact iPhone uses `TabView`; no duplicate screen behavior. Critical errors persist in Action Center rather than toast; VoiceOver labels identify avatar status and active model without requiring animation; Reduce Motion displays static asset. Settings changes transact to repository before indicating success; unavailable capabilities show explicit reason and no dead switch.

## A15: evaluation harness
Keep fixtures deterministic: 401, 429 with Retry-After, 5xx, malformed SSE, split UTF-8, canceled speech, task DST transitions, injected attachment instructions, two-user cross-session race, memory conflict, unknown model capability and StoreMigration fixture. Tests evaluate exact emitted events and persisted state; never judge model intelligence by brittle exact prose. Manual device matrix records model/OS/build/version and pass/fail evidence; absent iPad/Xcode means unverified, not PASS.
